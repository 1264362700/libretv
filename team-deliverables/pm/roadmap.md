# LibreTV / cl.tv 产品路线图与发布阶段计划

**版本**：v1.2  
**基准**：PRD v1.2 + 迭代计划 iteration-plan.md  
**产品**：LibreTV（cl.tv）视频聚合播放平台  
**技术栈**：Next.js 15 + TypeScript + Tailwind CSS，无需新增后端  
**优先级法**：MoSCoW（Must / Should / Could / Won't）  
**生效日期**：2026-11-05  

---

## 1. 产品定位与核心原则（摘录自 PRD）

- **元数据中心化**：首页、搜索、片库、详情统一由权威影视资料库驱动。
- **JIT 多源切片流匹配**：搜索与浏览与播放源完全解耦，点击播放瞬间并发测速选优，支持自动故障转移。
- **本地优先与纯隐私保护**：搜索历史、收藏夹、播放进度 100% 留存在用户设备 IndexedDB 中，无需注册，绝不上传云端。
- **无商业广告**：全站不出现插屏、贴片广告、弹窗广告。
- **无需新增后端**：全部基于现有 API/lib 能力。

## 2. MoSCoW 优先级汇总

### 2.1 优先级定义

| 优先级 | 定义 | 本版本交付要求 |
|--------|------|----------------|
| **Must (P0)** | 核心流程与关键体验基准，直接影响观影视听体验，无法缺失 | 本版本必须交付，QA 100% 通过验收标准 |
| **Should (P1)** | 重要体验增强，提升易用性与留存粘性，本版本推荐实现 | 本版本建议交付，资源受限可顺延 |
| **Could (P2)** | 进阶探索与扩展能力，资源充裕时逐步实现 | 可选，下一版本候选 |
| **Won't** | 本版本明确不纳入 | 明确排除，未来单独评估 |

## 3. 发布阶段计划

### 3.1 阶段概览

| 阶段 | 名称 | 目标 | 交付物 | 预计工期 | 负责 |
|------|------|------|--------|----------|------|
| 阶段 0 | 需求确认 | PRD 冻结，利益相关方对齐 | prd.md、roadmap.md、user-stories.md | 3 天 | Product Manager |
| 阶段 1 | MVP 核心观影流程 | 首页 + 播放页 + 登录页核心能力，可搜索、可播放、可断点续播 | 首页 Must 模块、播放页 Must 模块、登录页 Must 模块 | 10 天 | 全栈开发者 + QA |
| 阶段 2 | 体验增强与播放打磨 | 测速可视化、故障转移反馈、选集虚拟滚动、图片优化 | 播放页 Should 模块、首页 Should/图片优化 | 8 天 | 全栈开发者 + UI/UX 设计师 + QA |
| 阶段 3 | 内容发现与设置 | 片库页全功能、历史页、设置页核心能力 | 片库页 Must/Should、历史页 Should、登录页 Should、设置页 Should | 7 天 | 全栈开发者 + UI/UX 设计师 + QA |
| 阶段 4 | 可选增强与上线准备 | Could 模块选做、回归测试、性能调优、生产上线 | Could 模块选做、测试报告、上线 | 4 天 | 全栈开发者 + QA + Lead |

**总工期**：约 32 天（各阶段可部分并行，压缩至 24 天）

### 3.2 阶段 1：MVP 核心观影流程（Must）

**目标**：用户能打开首页、搜索影视、点击播放、登录后观看、断点续播。

**交付范围（Must 优先级）**：

| 模块 | 功能点 | 验收关键点 |
|------|--------|------------|
| 首页 | Hero 轮播（6 部趋势大片，≤3s 加载） | Hero 3 秒内显示 6 部大片 |
| 首页 | 官方精准搜索（TMDB，≤2s 返回卡片） | 搜索结果 2 秒内出现 |
| 首页 | 底层采集源深度扫描（多源并发，坏源不阻塞） | 各源结果逐条流式出现 |
| 首页 | 登录拦截（未登录点击播放跳转 /login?redirect=） | 跳转携带 redirect，登录后回跳 |
| 播放页 | 视频播放（ArtPlayer + hls.js，HLS/HTTP-FLV） | 首集自动播放 |
| 播放页 | 观看进度持久化（IndexedDB，续播误差 < 2s） | 刷新后从上次位置续播 |
| 登录页 | 账号登录 + 邀请码注册 | 正确账号密码登录成功，注册自动登录 |
| 登录页 | 已登录自动跳转 | 已验证用户访问 /login 自动跳回首页 |
| 全局 | 无商业广告、登录拦截回跳 | 全站无插屏/贴片/弹窗广告 |

**阶段 1 完成标准**：QA 对所有 Must 优先级验收标准 100% 通过。

### 3.3 阶段 2：体验增强与播放打磨（Should + 图片优化）

**目标**：提升播放体验可感知性，优化首屏图片加载，增强搜索发现。

**交付范围**：

| 模块 | 功能点 | 优先级 |
|------|--------|--------|
| 播放页 | 多源测速可视化面板（源名、延迟、QoS、当前/受阻标记） | Should |
| 播放页 | 自动故障转移 toast 提示（切换来源 → 切换目标） | Should |
| 播放页 | 选集虚拟滚动（100 集以上 60fps，DOM 不随集数线性增长） | Should |
| 播放页 | 追剧单（加入/移出，首页红点，自动同步最新集数） | Should |
| 播放页 | 跨屏接力（二维码，扫码从当前秒数续播） | Should |
| 播放页 | 剧集简介/演职员（官方元数据优先，采集源兜底） | Should |
| 首页 | 首屏图片加载优化（eager + 骨架屏 + 兜底，LCP ≤ 3s，失败率 ≤ 1%） | Must（图片优化 P0） |
| 首页 | 搜索历史与热词 | Should |
| 首页 | 官方搜索与底层源融合展示 | Should |
| 首页 | 源选择与成人过滤 | Should |

**阶段 2 完成标准**：播放页 Should 模块验收通过；首屏 LCP ≤ 3s；图片加载失败率 ≤ 1%。

### 3.4 阶段 3：内容发现与设置（Must + Should）

**目标**：完善片库浏览、观看历史、设置管理，形成完整内容发现与个性化设置闭环。

**交付范围**：

| 模块 | 功能点 | 优先级 |
|------|--------|--------|
| 片库页 | 分频道片库、多维筛选、深度搜索 | Must |
| 片库页 | 官方片库卡片、聚合卡片、分页导航 | Must |
| 片库页 | 登录拦截 | Must |
| 片库页 | 热门搜索词、搜索历史与热词 | Should |
| 历史页 | 观看历史列表、历史搜索、删除单条、清空历史、点击续播 | Should |
| 登录页 | 被顶号/封禁提示 | Should |
| 设置页 | 点播源管理、数据源订阅、播放与过滤、封面图加载 | Should |

**阶段 3 完成标准**：片库页所有 Must/Should 功能验收通过；历史页、设置页核心能力可用。

### 3.5 阶段 4：可选增强与上线准备（Could + 上线）

**目标**：选做 Could 模块，完成回归测试与性能调优，生产上线。

**交付范围**：

| 设置页 | 首页与内容（推荐数据源选择） | Could |

| 设置页 | 直播源管理 | Could |

**阶段 4 完成标准**：选做 Could 模块完成；所有阶段回归测试通过；生产环境上线并完成 smoke 测试。

## 5. 风险与依赖

| 风险项 | 说明 | 应对 |
|--------|------|------|
| 无需新增后端 | 本版本全部基于现有 API/lib 能力，无后端依赖 | 否 |
| 第三方源不稳定 | 采集站搜索/详情接口可能返回 HTML 错误页或超时 | 已有 SSRF 校验、JSON 格式校验、容错降级、超时隔离 |
| 图片源跨国延迟 | TMDB 海报、底层源海报依赖第三方图片源 | 复用首页图片优化成果（代理模式、骨架屏、懒加载） |
| Render 实例网络限制 | 线上站点部署在 Render，服务端代理请求上游可能受限 | 搜索与详情请求设置合理超时；服务端缓存（searchCacheKey 90s、detail 60s） |
| Master 分支红线 | 严禁直接 Push 到 Master，必须通过 PR 与 CI 门禁 | 走 feature/** 分支 + PR + CI 四项检查（typecheck/test/lint/build） |
