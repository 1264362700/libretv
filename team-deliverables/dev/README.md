# cl.tv

现代化全维流媒体视听与 IPTV 聚合平台，基于 Next.js 15、TypeScript 与 Tailwind CSS 构建。系统采用**元数据中心化 + JIT（即时）多源切片流匹配**的双层解耦架构，为用户提供极致纯净、无任何商业广告、注重个人隐私的高清观影体验。

> 本仓库为独立维护分支。部署、镜像与支持范围以本仓库为准。项目本身不内置任何影视内容、电视频道或第三方商业账号。

---

## 核心架构设计

系统彻底摒弃了传统采集站“搜索慢、海报糊、乱码广告多”的陈旧模式，采用业内前沿的现代流媒体双层解耦架构：

```
┌─────────────────────────────────────────────────────────────┐
│               全球权威影视元数据库 (Metadata Core)             │
│   (官方标准剧名 · 4K/高清海报 · 权威演职员名录 · 真实评分与剧情梗概)   │
└──────────────────────────────┬──────────────────────────────┘
                               │
               用户发起「搜索 / 探索片库 / 浏览热榜」
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                  高颜值纯净卡片网格与官方影视档案                 │
│              (毫秒级响应 · 杜绝牛皮癣广告 · 视觉统一)             │
└──────────────────────────────┬──────────────────────────────┘
                               │
                       用户点击「立即播放」
                               ▼
┌─────────────────────────────────────────────────────────────┐
│            JIT 即时切片流匹配引擎 (Playback Engine)           │
│       (数十条全球专线毫秒级并发测速 · 自动对齐集数 · 秒播起播)       │
│                · 智能动态故障转移 (Auto Failover)              │
└─────────────────────────────────────────────────────────────┘
```

1. **元数据中心化**：
   - 首页巨幕轮播、全站搜索、四维分类片库及影视详情档案，统一由全球权威影视资料库驱动。
   - 毫秒级极速响应，展示官方标准译名、4K/高清壁纸与海报、真实观众评分与完整剧情梗概，彻底告别采集站低质水印与赌博广告。
2. **JIT 即时切片流匹配**：
   - 搜索与浏览阶段与具体底层播放源完全解耦。
   - 仅在点击播放的瞬间，播放引擎全自动向全球数十条海外优质线路并发测速并优选最高可用线路秒播起播，若遇上游网络抖动自动无缝迁移至备用线路。

## 核心特性

- **权威元数据驱动搜索**：支持片名、原名全库极速精准搜索，展示统一规范的高颜值影视卡片与官方详情。
- **全网多源流式并发测速**：集成数十个高可用采集源矩阵，海外专线与蓝光无删减源权威置顶，后台全并发测速选优。
- **智能动态故障转移**：播放中遇到线路卡顿或切片异常时，引擎毫秒级自动切换至下一条备选高速线路，保留播放进度与集数。
- **本地优先与纯隐私保护**：搜索历史、收藏夹、播放进度 100% 留存在用户设备浏览器 IndexedDB 中，无需注册账号，绝不上传云端。
- **深度定制 HLS 播放器**：基于 ArtPlayer 与 hls.js 深度工程调优，支持智能跳过切片广告、自动连播、0.5x~3.0x 任意倍速、移动端长按 3 倍速快进、快捷键控制与影院宽屏模式。
- **直播 / IPTV 专区**：支持 M3U 播放列表订阅解析与 XMLTV 节目单（EPG），支持 HLS 与 HTTP-FLV 直播流播放及频道收藏。
- **端到端安全与防御**：服务端内置严格的 SSRF 校验（内网与保留地址阻断）与速率限制。

## 快速开始

需要 Node.js 22（与 Docker 及 CI 保持一致）或 Docker Compose。

```bash
cp .env.example .env
# 编辑 .env，至少设置一个强访问密码 PASSWORD
npm ci
PASSWORD=your-password npm run dev
```

开发服务器默认运行在 `http://localhost:8080`。

### 质量门禁与本地验证

```bash
npm run check   # typecheck + lint + 367 项单元测试 + 生产 build 打包
```

## 部署说明

### Docker（推荐）

```bash
# 在 .env 中设置 PASSWORD 后，从当前源码构建并启动
docker compose up -d --build
```

### Docker Compose 配置

```yaml
services:
  libretv:
    build: .
    container_name: libretv
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      - PASSWORD=change-me                   # 必填：访问密码，务必修改
      - TMDB_API_KEY=your-api-key            # 推荐：全球官方权威资料库 v3 API Key
      # - PROXY_SECRET=your-secret           # 会话/代理签名密钥（多实例部署建议显式设置）
      # - DEFAULT_SUBSCRIPTIONS=["https://example.com/sources.json"] # 预置数据源订阅
```

> ⚠️ **生产部署必须通过 HTTPS 访问**（localhost 除外）：生产环境下会话 Cookie 带 `Secure` 标记，仅在 HTTPS 环境下持久化。

## 环境变量参考

| 变量 | 必填 | 说明 |
| :--- | :---: | :--- |
| `PASSWORD` | **是** | 站点访问认证密码；未设置时站点会提示管理员配置 |
| `TMDB_API_KEY` | 否 | 全球官方权威影视资料库 v3 API Key；配置后全站首页、搜索、片库及影视档案全量接入高清权威资料库 |
| `PROXY_SECRET` | 否 | 会话/代理签名密钥；不设置时从 PASSWORD 派生 |
| `DEFAULT_SOURCES` | 否 | 预置点播采集源（JSON 数组），用户端自动加载并默认勾选 |
| `DEFAULT_LIVE_SOURCES` | 否 | 预置直播源（M3U 订阅），JSON 数组格式 |
| `DEFAULT_SUBSCRIPTIONS` | 否 | 预置数据源订阅（支持 JSON 链接与 TVBOX 配置地址），每 24h 静默同步 |
| `REQUEST_TIMEOUT` | 否 | 代理上游请求超时时间（毫秒），默认 `8000` |
| `COOKIE_SECURE` | 否 | 显式覆盖会话 cookie 的 `Secure` 标记（`true` / `false`） |
| `LIVE_ALLOW_PRIVATE` | 否 | 设为 `1` 时允许直播流代理访问内网/保留地址（自建内网 IPTV 场景） |

## 键盘快捷键

| 按键 | 功能 |
| :--- | :--- |
| `空格 (Space)` | 播放 / 暂停 |
| `←` / `→` | 快退 / 快进 5 秒 |
